# Three-node indicator advancement walkthrough

Prepared October 31, 2026. This is a manually stepped demonstration of the
ratified flow using existing diagnostic SET commands. It is not implemented
application-event input, automatic controller-owned advancement, or an event
identity/replay test. No firmware update is required. HOLD_OPEN is the agreed
name and means flashing green; no separate HOLD_ON state is introduced.

Each step holds indefinitely until the user requests the next step. The helper
commands the needed changes, then live-polls all three nodes against the table.
If any command/poll fails it stops advancing and marks the local test failed;
partial indications may remain. `stop` attempts OFF for every node and verifies
all three by live poll. There is no background test loop or automatic timer.
The controller's normal saved-intent reconciliation remains active.

| Step | Simulated event | Node1 | Node2 | Node3 |
| --- | --- | --- | --- | --- |
| 0 | Initialize | OFF | OFF | OFF |
| 1 | Head to 1 | ACTIVE | OFF | OFF |
| 2 | Another head to 1 | HOLD_OPEN | OFF | OFF |
| 3 | Head to 2 | LAST | ACTIVE | OFF |
| 4 | Another head to 2 | LAST | HOLD_OPEN | OFF |
| 5 | Head to 3 | OFF | LAST | ACTIVE |
| 6 | Another head to 3 | OFF | LAST | HOLD_OPEN |
| 7 | Head back to 2 | OFF | ACTIVE | LAST |
| 8 | Head back to 1 | ACTIVE | LAST | OFF |
| 9 | Finish | OFF | OFF | OFF |

ACTIVE = solid green; LAST = solid blue; HOLD_OPEN = flashing green. Node
commands still use normal 500 ms flash phases. Changing between indications
can briefly produce intermediate combinations because radio commands apply
sequentially, not atomically. The new destination is commanded first; final
results are checked by identity so returning to LAST never sends it a stale OFF.
FULL/FAULT are excluded from this advancement demonstration because they are
not generated by the normal head-destination advancement rules.

On Lin, use the UART virtual environment Python to run
`scripts/flow_walkthrough.py plan`, `start`, `next`, `status`, or `stop`.
`start` initializes OFF; each `next` performs one row. The ignored
`build/flow-walkthrough.json` records test progress only. It is not a controller
routing/event journal. Readiness/physical color observation requires the user.
Source preparation and Python syntax were checked; the walkthrough has not
been started. Existing final state from prior tests is all nodes OFF.
